# Экспериментальный Metal-рендер на Apple Silicon

Работа ведётся в ветке `simulator/mps-support`, созданной от
`simulator/mac-os-support`. Для Gazebo используется **OGRE 2 → Metal**.
MPS — библиотека GPU-операций, а не выбираемый движок рендера Gazebo.
Обоснование и первичные источники — в [исследовании](macos-metal-research.md).

В этом режиме **сервер Gazebo и его окно работают нативно на Mac**.
Это переносит на Metal также рендер сенсоров, включая камеру. PX4 и ROS
работают в Linux-контейнере. Окно открывается на рабочем столе
macOS; noVNC здесь не используется. Физика, PX4 и ROS-обработка изображений
не становятся MPS-вычислениями от выбора Metal.

## Что проверено 15 ноября 2026 года

| Проверка | Результат |
|---|---|
| Нативный draw call Metal с проверкой пикселей | PASS, устройство Apple M5 |
| Gazebo Harmonic arm64 | Установлен `gz-sim8` 8.15.0 через Homebrew |
| OGRE GUI | `Metal RenderSystem`, выбран `Apple M5`, Metal-шейдеры скомпилированы |
| Мир `obrik_aruco` и модель `x500_obrik_base_0` | Созданы нативно |
| Камера нативного сервера | Получен непустой RGB-кадр 1280×960 с ArUco-меткой; 3 686 400 байт |
| Docker ↔ Mac, TCP/UDP | Работают после включения host networking |
| Docker → native Gazebo control / native → Docker stats | PASS с мостом discovery; получены ответ сервиса и статистика мира |
| PX4 → native Gazebo | PX4 создаёт модель; работают IMU и управление моторами |
| Камера → ROS → ArUco → PX4 | Получена VIO, завершён GPS-to-ArUco handoff |
| Повторные полёты | Пять взлётов на 2 м и посадок с disarm без перезапуска |

Это экспериментальный режим с пятью последовательными полётами на Apple M5.
Исправлены гонка POSIX HRT и потеря обзора меток после посадки;
[подробная диагностика и границы проверки](macos-rearm-diagnosis.md).
Длительная стабильность пока не подтверждена. Обычный noVNC остаётся доступен по [основному гайду](guide.md).
Ускорение по FPS/real-time factor пока не измерено на одинаковом полётном сценарии.

## Установка и полный запуск

Основная инструкция находится в **[гайде установки симулятора — Metal](guide.md#macos-metal)**:
зависимости, host networking, загрузка образа, сервер, GUI, PX4/ROS, камера,
полёт и остановка. Для обычного запуска следуйте ей по порядку.
Для обычного запуска достаточно `./sim.sh start metal` из `simulation/compose`;
Ctrl+C останавливает всю сессию. Ниже оставлены низкоуровневые команды для
диагностики и объяснения устройства режима. Не запускайте их параллельно с `start metal`.

## 2. Проверить рендер без Docker-связи

### Терминал № 1 — на Mac

```bash
cd ~/vierret-sverk
```

```bash
python3 simulation/macos/metal_sim.py server
```

Оставьте сервер работать. На холодном старте загрузка библиотек может занять
до минуты. Он использует `--render-engine-server-api-backend metal` и автоматически
запускает локальную половину моста discovery. При Ctrl+C останавливаются оба процесса.

### Терминал № 2 — на Mac

```bash
cd ~/vierret-sverk
```

```bash
python3 simulation/macos/metal_sim.py gui
```

Должно открыться нативное окно Gazebo. GUI использует
`--render-engine-gui-api-backend metal`. Обе команды задают одинаковые
`GZ_PARTITION=sverk-metal` и `GZ_IP=127.0.0.1`: это устраняет выбор VPN/Wi-Fi
интерфейса при локальном discovery. В первичной проверке без явного loopback
окно не находило мир.

### Терминал № 3 — на Mac

Для независимой проверки камеры создайте модель без PX4:

```bash
cd ~/vierret-sverk
```

```bash
python3 simulation/macos/metal_sim.py spawn-base
```

Получите и проверьте один кадр:

```bash
python3 simulation/macos/metal_sim.py camera-check
```

При успехе появится `PASS: native camera 1280x960, …`.
Снимок находится в `simulation/macos/build/camera.png`; откройте его и
проверьте наличие поля/метки. Структурная проверка кадра не заменяет проверку
правильного содержимого и калибровки.

Сопоставьте результат с `~/.gz/rendering/ogre2.log`: нужны строки о выбранном
Metal RenderSystem и устройстве Apple, а не только имя GPU в `doctor`.

После этого теста нажмите **Ctrl+C** в терминалах сервера и GUI.
Перед интеграцией PX4 запустите сервер заново: модель должен создать сам PX4,
а не предыдущая команда `spawn-base`.

## 3. Как устроена связь Docker и нативного Gazebo

Один host networking не обеспечил Gazebo discovery в проверенной конфигурации.
Поэтому `server` и `up metal` автоматически запускают TCP-мост только для
обнаружения топиков и сервисов. Он слушает `127.0.0.1:19090`; multicast внутри
Mac использует порты 10317/10318, внутри Linux — 11317/11318. Разные UDP-порты
нужны, чтобы перенаправление Docker Desktop не заняло порты нативного Gazebo.
Камера, IMU и команды моторов идут через собственные TCP-соединения Gazebo.
`GZ_RELAY` в этом режиме очищается. Partition должен совпадать на обеих сторонах
(по умолчанию `sverk-metal`, переопределяется `SVERK_METAL_PARTITION`).

Также `up metal` автоматически готовит адрес XRCE-агента. В проверенной
конфигурации PX4 не устанавливал DDS-сессию с агентом через `127.0.0.1:8888`,
хотя агент работал. Использование адреса интерфейса Linux VM восстановило сессию.
Скрипт определяет адрес заново при запуске контейнера и сохраняет его в
`/tmp/sverk-xrce-agent.env`; внешний launch читает этот файл. Адрес вручную
копировать не нужно. В `rcS` добавлен выбор `PX4_UXRCE_DDS_HOST` с исходным
fallback `127.0.0.1`, поэтому обычный noVNC сохраняет прежний адрес агента.

## 4. Ограничения и остановка

- В нативной среде не загружаются Linux `.so` LED/servo/spray/optical-flow.
  Для этой ветки пока проверяются базовая модель и встроенные сенсоры Gazebo.
- Опоры нативной учебной модели и объектив 150° сохраняют обзор карты после посадки:
  камера примерно в 20 см над полом. Это отличается от геометрии исходного обрика.
  Посадка вне зоны видимости меток всё ещё может привести к потере VIO.
- Qt/GUI Material-шейдеры могут выдавать предупреждения; долгий прогон
  и полная работа GUI-панелей на Metal ещё требуют проверки.
- Нативный GUI и сервер могут писать в один `~/.gz/rendering/ogre2.log`.
  При проверке сенсоров сопоставляйте время запуска процессов и журнал.
- Сначала остановите ROS launch через **Ctrl+C** в контейнере.
- Затем остановите сервер и GUI через **Ctrl+C** в их терминалах на Mac.
- Контейнер останавливается на Mac из `simulation/compose`:

```bash
./sim.sh down metal
```

Сгенерированные модели, бинарник GPU-теста и кадры находятся в `build/`
и не включаются в Git. В этой ветке не изменяется основной noVNC-сценарий.
